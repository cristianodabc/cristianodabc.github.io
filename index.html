// 04 how I build with AI

AI writes much of the code. I own every line that ships.

↺ lessons from step 07 feed the next plan me AI agents

01Done by me and AI agents

Plan

I give an agent a short brief, and it challenges it with adversarial questions until the scope, data flow and risks are clear and the plan is agreed. Plans that need team input are published for review on Send Artifact.

02Done by AI agents

Build

Firstmate splits the plan into focused tasks, each handled by a worker in an isolated Herdr workspace. Model and effort are matched to each task’s complexity, and rtk and gh-axi keep tool output lean, so tokens go to the problem rather than overhead. Workers follow TDD, guided by my rules and Elixir skills.

03Done by AI agents

Verify

Each worker runs end-to-end QA on the development environment, covering the happy path and a failure path, then reports the evidence and stops before committing.

04Done by me

My review

I read, question and refine every diff. Nothing is committed without my approval.

05Done by AI agents and me

Gate

Every push passes through no-mistakes. In a disposable worktree it rebases, runs an AI code review, tests, documentation checks and linting, and fixes mechanical issues. Anything that changes intent comes back to me.

06Done by AI agents and me

Ship

The worker opens the pull request and requests team review. Agents resolve mechanical review comments, and larger changes come back to me. I run manual QA on staging before every release.

07Done by me and AI agents

Learn

Every mistake becomes a lasting safeguard: a hook that blocks it, a skill for that type of task, or a rule every session follows. The whole setup is versioned and tested in CI.

Elixir is my main stack, and I also take on Ruby and Python. I don’t take work in stacks I can’t review well, because AI-written code is only as good as the person checking it.
